# nubscroll

[English](README.md)

ThinkPad トラックポイントの中ボタンで、次の**両方**ができるようにする小さな Windows 常駐ツールです。

- 中ボタンを**クリック** → 通常の中クリック (タブを閉じる、リンクを新しいタブで開く等)
- 中ボタンを**押したまま**トラックポイントを倒す → 縦・横スクロール

Lenovo 公式ドライバではどちらか一方しか選べません。Linux (Xorg / libinput) では以前から両立できており、
nubscroll は同じ挙動を Windows で、余計な機能なしに実現します。

> **状態: 初期の試作版です。** 現在はコンソールプログラムとして動きます。トレイアイコン、
> 管理者権限での自動起動の切り替え、設定ファイルは未実装です ([今後の予定](#今後の予定) を参照)。

## なぜ新しく作るのか

既存の手段には、それぞれ次のような不足があります。

| ツール | 問題点 |
|---|---|
| TPMiddle | Synaptics の API に依存しており、ELAN 製トラックポイント (X390 以降) では動かない。メンテナンス停止 |
| W10Wheel.NET | 動作はするが、無関係な機能も多い汎用のホイールシミュレータ。管理者権限での自動起動は手動設定が必要 |
| X-Mouse Button Control / AutoHotkey | 実現はできるが、汎用ツールで手動の設定が必要 |

nubscroll は単機能で、ベンダーに依存しない (ベンダーの API ではなく OS のマウスイベントで処理する) こと、
自動起動を自分で管理し、exe を移動しても自動で直すことを目指しています。

## 使い方

```
nubscroll [オプション]
```

| オプション | 説明 |
|---|---|
| `--mode <scroll\|drag>` | 中ボタン＋移動の挙動 (既定: `scroll`)。`drag` は通常の中ボタンドラッグとして素通しする |
| `--threshold <PX>` | 中クリックとみなさなくなる移動距離 [px] (既定: 4) |
| `--sensitivity <N>` | 1px あたりのホイール量。120 で 1 ノッチ (既定: 10) |
| `--no-hwheel` | 横スクロールを無効にする |
| `--no-axis-lock` | 縦横を同時にスクロールする。既定では、スクロール開始時の移動方向の軸 (縦または横) だけに固定する。縦スクロールに横方向のぶれが混ざると、一部のアプリ (Windows の設定アプリなど) でスクロール位置が激しく振動するため |
| `--invert-v` / `--invert-h` | 縦 / 横スクロールの向きを反転する |
| `--quantize` | ホイールを 1 ノッチ単位でだけ送る (高分解能ホイールを正しく扱えないアプリ向け) |
| `--no-cursor` | スクロール中にカーソルを変えない。既定では、スクロールする軸を示す縦 / 横の矢印カーソルになる |
| `--hold-delay <MS>` | 中ボタンを押し続けてから、カーソルを四方向の矢印にするまでの時間。素早い中クリックでカーソルがちらつかないようにするため (既定: 200) |
| `--log <FILE>` | ログをファイルにも追記する |
| `--trace` | 中ボタン・ホイールのイベントを、ドライバが合成したものも含めて詳細にログ出力する (動作検証用) |
| `-h`, `--help` | ヘルプを表示する |

### ドライバの設定

Lenovo / Synaptics / ELAN のドライバ設定で、中ボタンを「スクロール」ではなく**「中クリック」**にしてください。
「スクロール」のままだとドライバが中ボタンを自前でホイールに変換してしまい、nubscroll から見えないことがあります。
OS が実際に何を受け取っているかは `--trace` で確認できます。`source=device` は物理デバイスからのイベント、
`source=injected` は他のソフトやドライバが合成したイベントです。

### 管理者権限のウィンドウ

Windows の UIPI の制限により、通常権限のプロセスからは管理者権限で動いているウィンドウ
(管理者として開いたターミナル等) をスクロールできません。そこでも使うには nubscroll を管理者として実行してください。
今後追加する自動起動機能で、これを自動で行う予定です。

## 仕組み

1. 低レベルマウスフック (`WH_MOUSE_LL`) で中ボタンの down を握りつぶして保留する。
2. 押下中の移動は握りつぶし (カーソルは固定)、移動量を累積する。閾値を超えたら `SendInput` でホイールに変換する。
3. 閾値を超える前に離されたら、保留していた down/up を中クリックとして送出する。

nubscroll 自身が送出したイベントは `dwExtraInfo` に目印を付け、フックで再処理しないようにしています。

## ビルド

Rust で書いています。Linux / WSL からクロスビルドできます。

```sh
sudo apt install mingw-w64
rustup target add x86_64-pc-windows-gnu
cargo win --release          # cargo build --target x86_64-pc-windows-gnu の別名
# → target/x86_64-pc-windows-gnu/release/nubscroll.exe
```

判定ロジックは OS に依存しないので、テストはどの環境でも実行できます。

```sh
cargo test
```
