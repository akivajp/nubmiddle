# nubmiddle

[English](README.md)

トラックポイント型のポインティングスティックの中ボタンに、スクロールを諦めずに中クリックを取り戻す、
小さな Windows 常駐ツールです。

- 中ボタンを**クリック** → 通常の中クリック (タブを閉じる、リンクを新しいタブで開く等)
- 中ボタンを**押したまま**スティックを倒す → 縦・横スクロール

Lenovo 公式ドライバではどちらか一方しか選べず、最近の ThinkPad では既定がスクロールになっています。Linux (Xorg / libinput) では以前から両立できており、
nubmiddle は同じ挙動を Windows で、余計な機能なしに実現します。

> **状態: 初期の試作版です。** リリースビルドはまだありません ([今後の予定](#今後の予定) を参照)。

### 対応デバイス

nubmiddle は OS のマウスイベントの段階で処理するので、中ボタンが本物の中ボタンとして Windows に届く
ポインティングスティックであれば動くはずです。動作確認は ThinkPad のトラックポイント・キーボード
(SK-8855、トラックポイント・キーボード II) で行っています。HHKB Studio など他社のスティックでも動く見込みですが、
未検証です (動作報告を歓迎します)。

## なぜ新しく作るのか

既存の手段には、それぞれ次のような不足があります。

| ツール | 問題点 |
|---|---|
| TPMiddle | Synaptics の API に依存しており、ELAN 製トラックポイント (X390 以降) では動かない。メンテナンス停止 |
| W10Wheel.NET | 動作はするが、無関係な機能も多い汎用のホイールシミュレータ。管理者権限での自動起動は手動設定が必要 |
| X-Mouse Button Control / AutoHotkey | 実現はできるが、汎用ツールで手動の設定が必要 |

nubmiddle は単機能で、ベンダーに依存しない (ベンダーの API ではなく OS のマウスイベントで処理する) こと、
自動起動を自分で管理し、exe を移動しても自動で直すことを目指しています。

## 使い方

```
nubmiddle [オプション]
```

nubmiddle はコンソールウィンドウを開かず、通知領域 (タスクトレイ) に常駐します。メニューには次の項目があります。

- **Middle button + move**: 中ボタンを押したまま動かしたときの動作を、*Scroll* (既定) と
  *Middle-button drag* (スクロールせず、通常の中ボタンドラッグ。CAD や Blender の画面移動向け) から選びます。
  中クリックはどちらでも同じです。
- **Vertical / Horizontal scroll speed**: 縦・横それぞれ、既定値の x0.5 から x2 までの5段階です。
- **スクロールするデバイス**: すべてのマウス・ポインティングデバイス (既定) か、接続中のデバイスの一覧で
  チェックしたものだけかを選びます。それ以外のデバイスでは中ボタンが普通の中ボタンのままなので、
  トラックポイントではスクロールしつつ、マウスでは Blender などで中ボタンドラッグを使えます。
  デバイスは Raw Input で見分け、ベンダー ID と製品 ID (例: `17EF:6009`) で保存します。
- **Reset to defaults** (既定値に戻す)、**Open settings file** (設定ファイルを開く)、
  **Reload settings file** (設定ファイルを読み込み直す)
- **Language / 言語**: 英語か日本語。既定では Windows の表示言語に合わせます。

- **Start with Windows (as administrator)**: ログオン時に nubmiddle を管理者権限で起動するタスクを、
  タスクスケジューラに登録します (切り替え時に UAC の確認が1回出ます。ログオン時には出ません)。
  タスクは、実行中の nubmiddle と同じオプションで起動します。exe を移動した場合は
  「update to this exe」に変わります。管理者権限で動いている場合は、自動で登録し直します。
- **Pause**: チェックを外すまで、すべてのマウスイベントをそのまま通します。
- **Quit**: 終了します。

同時に起動できるのは1つだけです。コンソールから起動した場合、`--help` とログはそのコンソールに表示されます。

### 設定ファイル

メニューで変えた設定はすぐに反映され、`nubmiddle.ini` に保存されます。保存先は次のとおりです。

- exe と同じフォルダに `nubmiddle.ini` があれば、そのファイル (ポータブル運用。同期フォルダに exe を置く場合など)
- 無ければ `%APPDATA%\nubmiddle\nubmiddle.ini`
- `--config <FILE>` で指定した場合は、そのファイル

各行は `key = value` の形式で、キーは `mode`、`threshold`、`sensitivity_v`、`sensitivity_h`、`horizontal`、
`axis_lock`、`invert_v`、`invert_h`、`quantize`、`cursor`、`hold_delay_ms` (意味は下のオプションを参照) と、
`language` (`auto`、`en`、`ja` のいずれか)、`devices` (`all` か、`17EF:6009, 04FE:0021` のように
カンマで区切った ID) です。
コマンドラインのオプションは、メニューで同じ設定を変えるまでは、ファイルより優先されます。
なお自動起動のタスクは、登録した時点の nubmiddle と同じオプションで起動します。

| オプション | 説明 |
|---|---|
| `--mode <scroll\|drag>` | 中ボタン＋移動の挙動 (既定: `scroll`)。`drag` は通常の中ボタンドラッグとして素通しする |
| `--threshold <PX>` | 中クリックとみなさなくなる移動距離 [px] (既定: 4) |
| `--sensitivity <N>` | 縦横共通の 1px あたりのホイール量。120 で 1 ノッチ (既定: 10) |
| `--sensitivity-v <N>` / `--sensitivity-h <N>` | 同上。縦 / 横だけに適用する |
| `--no-hwheel` | 横スクロールを無効にする |
| `--no-axis-lock` | 縦横を同時にスクロールする。既定では、スクロール開始時の移動方向の軸 (縦または横) だけに固定する。縦スクロールに横方向のぶれが混ざると、一部のアプリ (Windows の設定アプリなど) でスクロール位置が激しく振動するため |
| `--invert-v` / `--invert-h` | 縦 / 横スクロールの向きを反転する |
| `--quantize` | ホイールを 1 ノッチ単位でだけ送る (高分解能ホイールを正しく扱えないアプリ向け) |
| `--no-cursor` | スクロール中にカーソルを変えない。既定では、スクロールする軸を示す縦 / 横の矢印カーソルになる |
| `--hold-delay <MS>` | 中ボタンを押し続けてから、カーソルを四方向の矢印にするまでの時間。素早い中クリックでカーソルがちらつかないようにするため (既定: 200) |
| `--config <FILE>` | 使う設定ファイル ([設定ファイル](#設定ファイル) を参照) |
| `--log <FILE>` | ログをファイルにも追記する |
| `--trace` | 中ボタン・ホイールのイベントを、ドライバが合成したものも含めて詳細にログ出力する (動作検証用) |
| `-h`, `--help` | ヘルプを表示する |

### ドライバの設定

Lenovo / Synaptics / ELAN のドライバ設定で、中ボタンを「スクロール」ではなく**「中クリック」**にしてください。
「スクロール」のままだとドライバが中ボタンを自前でホイールに変換してしまい、nubmiddle から見えないことがあります。
OS が実際に何を受け取っているかは `--trace` で確認できます。`source=device` は物理デバイスからのイベント、
`source=injected` は他のソフトやドライバが合成したイベントです。

### 管理者権限のウィンドウ

Windows の UIPI の制限により、通常権限のプロセスからは管理者権限で動いているウィンドウ
(管理者として開いたターミナル等) をスクロールできません。そこでも使うには nubmiddle を管理者として実行してください。
トレイメニューの「Start with Windows」を使えば、これを自動で行います。

## 仕組み

1. 低レベルマウスフック (`WH_MOUSE_LL`) で中ボタンの down を握りつぶして保留する。
2. 押下中の移動は握りつぶし (カーソルは固定)、移動量を累積する。閾値を超えたら `SendInput` でホイールに変換する。
3. 閾値を超える前に離されたら、保留していた down/up を中クリックとして送出する。

nubmiddle 自身が送出したイベントは `dwExtraInfo` に目印を付け、フックで再処理しないようにしています。

## ビルド

Rust で書いています。Linux / WSL からクロスビルドできます。

```sh
sudo apt install mingw-w64
rustup target add x86_64-pc-windows-gnu
cargo win --release          # cargo build --target x86_64-pc-windows-gnu の別名
# → target/x86_64-pc-windows-gnu/release/nubmiddle.exe
```

判定ロジックは OS に依存しないので、テストはどの環境でも実行できます。

```sh
cargo test
```

アイコン (`assets/nubmiddle.ico`、`assets/nubmiddle-paused.ico`) はスクリプトで生成し、ビルド時に exe へ埋め込んでいます。
変えるときは、スクリプトを編集して実行し直してください。

```sh
uv run assets/make_icons.py --preview preview.png
```
