# MSIX package (Microsoft Store)

nubmiddle's package for the Microsoft Store. The same `nubmiddle.exe` as in the zip and the installer; from a package it:

- keeps the settings file in the package's folder, `%LOCALAPPDATA%\Packages\<package family name>\LocalState` (Windows redirects a packaged app's writes to `%APPDATA%` into a private copy, which Notepad, opened from the tray, would not see). Uninstalling removes it;
- starts with Windows through the package's startup task (`windows.startupTask` in the manifest), not a scheduled task. A startup task runs without administrator rights, so the Store version does not scroll windows that run as administrator (an elevated terminal, for example); the installer and the zip can.

## Building

The release workflow (`.github/workflows/release.yml`) builds the package for x64 and ARM64 on every tag, and when run by hand. The artifacts `nubmiddle-msix-x64` and `nubmiddle-msix-arm64` hold:

- `nubmiddle-vX.Y.Z-<arch>.msix`: for Partner Center (unsigned; the Store signs what it publishes);
- `nubmiddle-vX.Y.Z-<arch>-test.msix` and `-test.cer`: a copy signed with a throwaway self-signed certificate, for trying the package;
- `wack-report.xml` (x64 only): the Windows App Certification Kit's report on the package (the checks Partner Center runs).

On Windows with the Windows SDK, the same by hand:

```powershell
cargo build --release --target x86_64-pc-windows-msvc
./packaging/msix/build.ps1 -Exe target/x86_64-pc-windows-msvc/release/nubmiddle.exe -Version 0.4.0 -Arch x64 -OutDir dist -TestSign
```

The images in `Assets/` and the Store's box art (`StoreBoxArt-1080.png`) are generated by `assets/make_icons.py`, each size on its own. `build.ps1` indexes them with makepri so that Windows picks the right one.

## Trying the test copy

1. Trust the certificate (as an administrator): `Import-Certificate -FilePath nubmiddle-vX.Y.Z-x64-test.cer -CertStoreLocation Cert:\LocalMachine\TrustedPeople`
2. Install, from a signed-in session (over SSH it fails with 0x80070005, access denied): `Add-AppxPackage nubmiddle-vX.Y.Z-x64-test.msix`
3. Start it from the Start menu, or `explorer.exe "shell:AppsFolder\<package family name>!nubmiddle"`.
4. Remove it: `Get-AppxPackage *nubmiddle* | Remove-AppxPackage`, then the certificate from `Cert:\LocalMachine\TrustedPeople`.

## Publishing on the Store

The repository variables `MSIX_IDENTITY_NAME`, `MSIX_PUBLISHER` and `MSIX_PUBLISHER_DISPLAY_NAME` carry the Store's identity (Partner Center > Product identity) into the package. The first submission is made in Partner Center by hand (`store-listing.ja.md`); later ones go through the Microsoft Store workflow (`.github/workflows/msstore.yml`) with the listing files in `store/`.

Each version needs a new package version (the workflow takes it from `Cargo.toml`); the Store's last number stays 0.
